# Еврокубки: параллельная статистика из национальных чемпионатов

Составлен 2026-09-05 перед стартом фэнтези Лиги чемпионов 2026/27 (сезон
Sports.ru `#85`, дедлайн 1-го тура — **2026-09-08 16:45 UTC**). Цель — прогноз
для ЛЧ и Лиги Европы, который опирается на то, как игроки и клубы выступают
*сейчас* в своих чемпионатах, а не только на 0–8 матчей самого еврокубка.
Все факты ниже проверены живыми запросами к Sports.ru и локальной БД в день
составления.

## Что уже есть и что проверено

### Матчинг игроков и клубов не нужно изобретать

Стат-слаги Sports.ru глобальны, а не привязаны к турниру, и схема уже
опирается на это: `players.stat_player_id` и `clubs.stat_team_id` — UNIQUE
на всю базу, поэтому один и тот же человек в двух лигах — одна строка
`players` с двумя `player_seasons`.

| Проверка | Результат |
| --- | --- |
| Игроки, уже сидящие в двух лигах локальной БД | `cesar_montes`, `giovanni_gonzalez`, `vanja_drkusic`, `nabil_aberdin`, `victor_parada` — по одной строке `players`, сезоны и РПЛ, и Ла Лиги |
| 5 испанских клубов ЛЧ (`real_madrid`, `barcelona`, `atletico_madrid`, `villarreal_cf`, `real_betis_balompie`) | все уже существуют в `clubs` — импорт ЛЧ переиспользует строки |
| Ростеры этих 5 клубов в ЛЧ (167 игроков) | 153 совпадают с `player_seasons` Ла Лиги 2026/27 по слагу; 14 несовпавших — молодёжь/резерв, которой нет в каталоге Ла Лиги |

То есть «научиться матчить» сводится к тому, чтобы импортировать сезон
еврокубка тем же `fantasy-ingest`: `DomainImportRepository` найдёт игрока и
клуб по слагу. Нечёткий матчинг по именам не нужен; для несовпавших игроков
(нет ни в одной импортированной лиге) остаются позиционные прайоры.

## Чего не хватает в коде

1. **Один источник истории.** `build_feature_dataset` читает матчи и выходы
   только из активного снапшота целевого сезона и одного *предыдущего сезона
   той же лиги* (`resolve_prior_run`). Для ЛЧ «предыдущий сезон» — лиговая
   фаза 25/26 (`#70`): 8 матчей, половина клубов другие. Национальный
   чемпионат в модель не попадает вообще.
2. **Сила клубов без нормировки между лигами.** `team_goal_means` намеренно
   «без общелиговой нормировки»: 2.4 гола за матч дома в Ла Лиге и 2.4 в
   Элитсерии — разные вещи, когда обе команды встречаются в ЛЧ.
3. **Доступность.** Снапшот ЛЧ говорит `UNKNOWN` про всех; травмы известны в
   снапшоте национальной лиги. Красная карточка, наоборот, действует только
   внутри своего турнира: `red_card_suspension` нельзя переносить между
   источниками.
4. **Ротация.** Доля выходов в чемпионате не равна доле выходов в ЛЧ:
   топ-клубы ротируют против слабых соперников группы, а середняки ставят
   сильнейший состав. Пока это неизвестная величина, которую можно измерить
   только бэктестом.
5. **Провенанс.** `stat_source` умеет только `current_season` /
   `prior_season`; фронт должен видеть, что цифра игрока «Реала» пришла из
   Ла Лиги.

## Как учитывать параллельную статистику

Принцип: **ставки игрока — из всех его матчей текущего окна, сила клуба и
ожидаемые голы — из котировок конкретного матча, а чемпионат — прайор к ним.**

### Источники истории игрока

Для целевого сезона еврокубка история игрока собирается из трёх слоёв, все
строго `scheduled_at < cutoff` целевого тура (национальный чемпионат идёт
параллельно, поэтому фильтр по дате обязателен и в проде, и в бэктесте):

| Слой | Откуда | Вес |
| --- | --- | --- |
| Собственные матчи еврокубка | активный снапшот ЛЧ | 1.0, как сейчас `current` |
| Национальный чемпионат, текущий сезон | активный снапшот лиги, `player_season` того же `player_id` | `PARALLEL_WEIGHT` (старт 0.7), окно `RATE_PRIOR_WINDOW` |
| Национальный чемпионат, прошлый сезон | `resolve_prior_run` лиги | как сейчас: `prior_season_weight`, но по числу матчей *суммарно* в первых двух слоях |

Прошлый сезон лиги нужен обязательно: к 8 сентября в чемпионатах сыграно 3–4
тура, и без 25/26 «Мбаппе» описывался бы тремя матчами.

Per-90 ставки (голы, ассисты, сэйвы, подборы, карточки, `ninety_share`)
переносятся напрямую — правила начисления те же. Роль берётся из целевого
сезона (игрок может быть DEF в лиге и MID в ЛЧ), усадка — к среднему по роли
*пула ЛЧ*.

Игрок, которого нет ни в одной импортированной лиге (14 из 167 у испанцев,
все семь клубов без лиги), остаётся `is_newcomer` с прайорами по позиции.

### Доля выходов и доступность

- `appearance_share` / `start_share` — из объединённых слоёв с теми же
  весами; собственные матчи ЛЧ по мере накопления перевешивают, ровно как
  сейчас текущий сезон перевешивает прошлый.
- Статус — самый свежий из снапшотов всех сезонов игрока (по `captured_at`);
  `INJURY` в любом источнике зануляет, `QUESTIONABLE` — половинит.
- `red_card_suspension` и «второй матч после прямой красной» считаются только
  внутри целевого турнира.
- Поправка на ротацию (`ROTATION_FACTOR` по группам «топ-клуб / остальные»)
  вводится только по результату бэктеста; до него = 1.0.

### Сила клубов и ожидаемые голы

1. Базовая сила клуба — `_club_strengths` по матчам национальной лиги
   (текущий + прошлый сезон через `_blended_club_matches`), умноженная на
   коэффициент лиги: `attack × LEAGUE_FACTOR[league]`,
   `defense / LEAGUE_FACTOR[league]`. Коэффициенты — константы в коде с
   документированным источником; стартовые значения подбираются бэктестом ЛЧ
   25/26 (см. ниже), до него — из соотношения средних голов лиг.
2. Собственные матчи ЛЧ входят в тот же пул с весом 1.0 и постепенно
   вытесняют чемпионат.
3. Поверх — котировки с существующим `DEFAULT_ODDS_WEIGHT` 0.6. Это и есть
   главная кросс-лиговая нормировка: `attack_scale = odds_goals_for /
   hist_goals_for` уже масштабирует голы и ассисты каждого игрока к ожидаемым
   голам клуба *в этом матче*. Когда линия есть, ошибка `LEAGUE_FACTOR`
   стоит немного; когда линии нет (7 клубов без лиги или тур без линии) —
   работает п. 1 или среднее по пулу ЛЧ.

### Провенанс

- `stat_source` получает значения `parallel_league` (история в основном из
  чемпионата) поверх существующих; в строку признаков добавляется
  `sources: [{competition, season, appearances, weight}]`, чтобы фронт и
  бэктест видели состав истории.
- `FEATURE_VERSION` → `1.8.0`.

## Что *не* нужно менять

- Схему БД (кроме, возможно, `competitions.kind` — `league | cup | national`,
  чтобы Чемпионат мира и Лига наций не считались параллельным источником).
  Связь «клуб → его чемпионат» выводится из данных: у клуба есть
  `season_clubs` в активном сезоне другой лиги, пересекающемся по датам.
- `SCORING`, оптимизатор, чтение правил и лимитов по турам.
- Ингест и quality gate — ожидаемо работают, проверить на 36 клубах и
  двухфазных сезонах (п. 24.1).

## Шаг 24: план работ

24.1. **Импорт.** ЛЧ 26/27 (`#85`), национальные лиги `england`, `germany`,
`italy`, `france`, `portugal`, `netherlands`, `turkey`, `eliteserien` за
26/27 и 25/26, плюс ЛЧ 25/26 лиговая фаза (`#70`) и ЛЕ 25/26 (`#71`) для
бэктеста. Проверить quality gate на 36 клубах и на паре сезонов с одним
`stat_season_id`. Отчёт: доля ростера каждого клуба ЛЧ, найденная в лиге.
Ночной refresh автоматически подхватит новые лиги (~45 с каждая).

24.2. **Параллельные источники в `features.py`.** Загрузка слоёв из других
активных сезонов по `player_id` / `club_id` с отсечкой по `cutoff`,
веса, объединённая доступность, красные карточки в границах турнира,
`sources` и новый `stat_source`. Юнит-тесты на отсечку (матч лиги после
дедлайна ЛЧ не попадает в историю) и на выбор самого свежего статуса.

24.3. **Сила клубов между лигами.** `LEAGUE_FACTOR`, пул «чемпионат + ЛЧ»,
проверка, что `odds_refresh` для `champions-league` и `europa-league` пишет
`match_odds` (двухфазный сезон: календарь один, фэнтези-сезонов два).

24.4. **Бэктест ЛЧ 25/26** с лигами 25/26 как параллельными источниками
(`fantasy-backtest` уже умеет `history_before` по котировкам). Базовая линия —
«только ЛЧ + прайоры новичков». Критерии приёмки те же три, что в
[`forecast-improvement-plan.md`](forecast-improvement-plan.md): MAE по всем,
MAE по игравшим, очки составов; по бэктесту фиксируются `PARALLEL_WEIGHT`,
`LEAGUE_FACTOR` и решение по `ROTATION_FACTOR`.

24.5. **UI.** Метка источника в карточке игрока и списке (как сейчас для
`prior_season`), в админке — ничего нового: импорт по slug уже общий.

24.6. **Лига Европы** — тот же код; отличие только в доле покрытых клубов.

### Минимум до дедлайна 1-го тура (08.09)

24.1 + 24.2 + котировки через существующий `odds_refresh`; `LEAGUE_FACTOR`
и `PARALLEL_WEIGHT` — стартовые константы, бэктест (24.4) — после тура.

## Риски

- Совпадение слагов проверено на Ла Лиге; у других лиг возможны дубли вида
  `cheikh_thiam` / `cheikh_ahmad_tidiane_thiam` (оба в ростере Вильярреала в
  ЛЧ). Отчёт 24.1 покажет масштаб.
- Линии на ЛЧ могут появиться позже дедлайна конкретного тура — тогда
  работает п. 1 без котировок, поэтому `LEAGUE_FACTOR` нельзя оставлять 1.0.
- Sports.ru замораживает статистику через 72 ч после тура; для лиг, играющих
  в выходные перед вторником ЛЧ, ночной refresh может подхватить неполные
  цифры — то же ограничение, что и сейчас внутри одной лиги.
