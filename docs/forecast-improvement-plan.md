# План дальнейших улучшений прогноза

Составлен 2026-09-04 по итогам шага 22 (калибровка прогноза, см.
[`development-history.md`](development-history.md)). Выполнен шагом 23 в тот
же день; статус каждого пункта — в разделе «Статус выполнения» внизу, цифры и
решения — в карточке шага 23.

Точка отсчёта для каждого
пункта — бэктест на полных сезонах 2025/26 РПЛ и Ла Лиги с прошлым сезоном
2024/25 (`fantasy-backtest --run-id 1` и `--run-id 2` в локальной БД) плюс
сыгранные туры текущих сезонов 2026/27. Любое изменение принимается только если
не ухудшает три критерия вердикта (MAE по всем, MAE по игравшим, очки составов)
и сокращает разрыв между спрогнозированными и фактическими очками топ-25.

## Где модель слаба сейчас

| Наблюдение | Значение | Что это значит |
| --- | --- | --- |
| Ранговая корреляция прогноза с фактом среди игравших | 0.34 (РПЛ), 0.32 (Ла Лига) | Порядок игроков внутри тура угадывается слабо; это главный резерв |
| Очки составов против hindsight-оптимума | 1837 из 3753 (РПЛ 25/26) | Половина — потолок случайности, но разрыв большой |
| Смещение по игравшим | −0.9 … −1.0 очка на строку | Условно на выход модель занижает: часть очков не моделируется |
| Немоделируемые очки (пенальти, автоголы, красные) | 3–4 % всех очков | Их нет в компонентах вообще |
| Котировки | только накануне тура, истории нет | Вес 0.6 не проверен бэктестом |
| Капитан | попадание в лучшего стартера 27 % | Выбор по среднему, а не по верхнему хвосту |

## Приоритет 1. Ранжирование внутри тура

1. **Признаки «мудрости толпы».** `selected_by` (владение) и цена — сильные
   априорные оценки, которых модель не использует. Первый шаг: усадка ставок не
   к среднему по позиции, а к среднему по ценовой корзине позиции (цена 4.5 и
   цена 10.0 — разные прайоры). Второй шаг: смешать `p_appearance` с
   владением (популярного игрока выставляют, потому что он играет).
   Проверка: ранговая корреляция и топ-25 в бэктесте.
2. **Обученная модель поверх признаков.** Градиентный бустинг (или просто
   регуляризованная регрессия) на текущем датасете признаков с целевой
   переменной «очки за тур», обучение walk-forward по турам, бэктест как
   ворота. Событийная модель остаётся объяснимым baseline, обученная —
   отдельным `model_name` в `player_forecasts`, чтобы фронт мог переключать.
   Не включать в оптимизатор по умолчанию, пока не выиграет по всем трём
   критериям в обеих лигах.
3. **Спад внутри текущего сезона для ставок.** Сейчас `CURRENT_RECENCY_DECAY`
   применяется только к доле выходов и минутам; голы/ассисты за август и за
   вчера весят одинаково. Добавить экспоненциальный спад (кандидаты 0.9–0.95
   за матч) и перебрать в связке с `RATE_SHRINK_MATCHES`.

## Приоритет 2. Ожидаемые минуты и доступность

4. **Статус из снапшота как признак, а не только фильтр.** `status_description`
   («травма, ~2 недели», «под вопросом») сейчас либо обнуляет игрока, либо
   игнорируется. Разобрать словарь описаний (двух лиг хватит), выделить
   «под вопросом» в отдельную вероятность (например ×0.5) и «вернулся» как
   сброс спада отсутствия.
5. **Смена клуба внутри сезона.** Игрок, перешедший в другой клуб, наследует
   долю выходов по старому клубу. Считать долю по матчам нового клуба с момента
   перехода (по `season_club_id` в `player_match_stats`).
6. **Красная карточка на два и более тура.** Сейчас любая красная — один матч.
   Sports.ru не отдаёт длительность; можно брать из `status_description`
   (пункт 4) или считать вторую жёлтую как один матч, прямую — как два.

## Приоритет 3. Матчевая модель

7. **История котировок.** Сохранять линию 1x2 при каждом ночном обновлении
   (не только накануне тура), чтобы бэктест мог проверить `DEFAULT_ODDS_WEIGHT`
   и, возможно, поднять его. Пока котировок в бэктесте нет, вес 0.6 — гипотеза.
8. **Форма клуба.** Клубные силы усаживаются к среднему по лиге, но внутри
   сезона не спадают: 4-0 в августе и 4-0 вчера равны. Добавить тот же спад,
   что и игрокам, и перебрать окно `STRENGTH_PRIOR_WINDOW` заново — на полном
   сезоне оно нейтрально, но в первые 5 туров может решать.
9. **Домашнее поле явным множителем.** Сейчас площадка учитывается тем, что
   силы считаются по домашним и выездным матчам раздельно, и это вдвое режет
   выборку. Общая сила клуба × лиговый домашний множитель даст вдвое больше
   матчей на оценку при той же информации.
10. **Немоделируемые события.** Пенальти (по `penalties_target` / `penalties_saved`
    в `player_match_stats`), автоголы и красные как отдельные компоненты с
    ролевыми ставками. Это закроет ~3–4 % очков и часть отрицательного
    смещения по игравшим.

## Приоритет 4. Оптимизатор и замены

11. **Капитан по верхнему хвосту.** Вместо `argmax` ожидания — `argmax`
    ожидания + k × неопределённость (неопределённость уже считается), k
    подобрать по доле попаданий в лучшего стартера в бэктесте.
12. **Замены на горизонт 2–3 туров.** Лимит замен не переносится, но игрок
    остаётся в составе: целевая функция — сумма ожиданий по следующим N турам
    со спадом (сложность календаря, сдвоенные и пустые туры). Нужна сборка
    признаков сразу на несколько туров вперёд.
13. **Порог выгоды замены по неопределённости.** `min_transfer_gain` сейчас
    константа 0.5; логичнее требовать выгоду не меньше доли стандартного
    отклонения разности двух прогнозов.
14. **Скамейка с учётом вероятности выхода.** Очки со скамейки идут в зачёт
    при автозамене; порядок скамейки должен максимизировать ожидание с учётом
    `p_appearance` стартеров, а не сортировать по ожиданию.

## Приоритет 5. Данные и инфраструктура проверки

15. **Импорт РПЛ 2024/25 через продукт.** Sports.ru отдаёт пустую страницу
    игроков из-за одного нечитаемого игрока (`got nil for non-null
    "statPlayer"`). Добавить в клиент повторный запрос страницы по одному
    игроку с пропуском сломанного и предупреждением в `data_quality_issues`.
16. **Бэктест сразу по нескольким лигам.** Одна команда, сводная таблица по
    лигам, чтобы любое изменение модели проверялось на 68+ турах, а не на
    одной лиге.
17. **Метрики ранжирования в отчёте бэктеста.** Ранговая корреляция по
    игравшим, очки топ-25 против факта, разрыв прогноз/факт по составам —
    это то, что увидел пользователь, и этого нет в текущем отчёте.
18. **Ещё один прошлый сезон для Ла Лиги и РПЛ (2023/24).** Даст третий
    полный сезон для перебора констант и снизит риск подгонки под 2025/26.

## Что не стоит делать

- Поднимать веса прошлого сезона обратно: и полный сезон, и текущие туры
  показали, что 3 матча полураспада и окно 8 матчей лучше прежних значений.
- Уменьшать `RATE_SHRINK_MATCHES` ниже 3: усадка 5 выиграла у 0, 2 и 3 по
  всем метрикам в обеих лигах.
- Тюнить константы на текущем сезоне 2026/27: 3–6 туров — это шум; проверять
  на нём можно, подбирать нельзя.
